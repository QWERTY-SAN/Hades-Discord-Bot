# Hades conversation improvements

This is an **overlay patch**, not a full repository archive. Extract it into the root of your existing `Hades-Discord-Bot` checkout and allow the two `hades_bot/ai/` files to be replaced. It intentionally leaves commands, deployment settings, memory storage, scope enforcement, GIF behavior, and dependencies unchanged.

## Changes

- **Better continuity:** Hades is directed to resolve short follow-ups, pronouns, callbacks, and jokes from the actual recent exchange instead of responding as if each message were new.
- **Less repetitive roleplay:** The prompt explicitly rejects fixed reply lists, rigid response formulas, repetitive nicknames, constant stage directions, and forced questions at the end of every message.
- **More natural fan banter:** Adds intent detection for more indirect fan reactions, playful command requests, gentle affection, and flustered admiration.
- **Still Hades:** Keeps the existing Aether Gazer identity, canon-first guidance, topic restrictions, restrained theatrical style, optional emojis, and non-explicit fan-service boundary.
- **No response templates:** Fan-service code supplies model guidance only. It does not select or send canned reply strings.
- **No deployment changes:** Does not add environment variables or dependencies.

## Apply and verify

1. Make a backup or commit your current working tree.
2. Extract this archive into the existing repository root, preserving folders.
3. From the repository root, run `python -m unittest tests.test_conversation_persona`.
4. Run the project's existing tests before deploying to Render.

The tests cover intent detection and persona prompt invariants. They do not call Discord or Gemini and cannot guarantee a specific generated response, since the response is still generated by Gemini at runtime.
